# بيتزرية 450 — الحكاية

تجربة قصة تفاعلية سينمائية: الموقع فيلم قصير، والـScroll هو زر التشغيل.
كل حركة للعجلة تحرّك الكاميرا والضوء والأحداث إلى الأمام أو إلى الخلف.

**من فكرة صغيرة... إلى بيتزرية 450.**

React 19 · GSAP ScrollTrigger · Lenis · Three.js · React Three Fiber · Vite

---

## التشغيل

```sh
npm install
npm run dev        # http://localhost:5173
npm run build      # نسخة الإنتاج في dist/
npm run preview    # معاينة نسخة الإنتاج
```

يحتاج Node 20.19+ أو 22.12+ (تمت التجربة على Node 24).

روابط مفيدة أثناء التعديل:

| الرابط | ماذا يفعل |
| --- | --- |
| `/?scene=pizza` | يفتح الفيلم مباشرة على مشهد معيّن (`sunrise`, `people`, `place`, `build`, `pizza`, `firstTable`, `growth`, `reveal`, `finale`) |
| `/?t=14` | يفتح على زمن معيّن من الفيلم (بوحدة "شاشات") |
| `/?quality=low` | يجرّب نسخة الهواتف الأخف (`low` / `medium` / `high`) |
| `/?nowebgl` | يجرّب ما يراه جهاز لا يدعم الـ3D (صور ثابتة بدل المشاهد ثلاثية الأبعاد) |

## تعديل النصوص

**كل النصوص والصور والروابط في ملف واحد:** [`src/data/story.js`](src/data/story.js)

- النص بين قوسين مربعين مثل `[ضع هنا ...]` هو **مكان لمعلومة حقيقية** ويظهر على الشاشة بخط منقّط. حاليًا لا يوجد أي مكان فارغ؛ هذه الطريقة متاحة إن أضفت مشاهد جديدة.
- عند الإطلاق ضع `SHOW_PLACEHOLDERS = false` لإخفاء أي مكان فارغ بقي.
- الكلمة بين نجمتين `*الحلم*` تظهر بلون ذهبي دافئ.
- `duration` لكل مشهد = طوله بعدد "الشاشات" من الـScroll. رقم أكبر = مشهد أبطأ.
- `PACE` في آخر الملف يتحكم بسرعة الفيلم كله (على الكمبيوتر وعلى الهاتف).

### أسلوب النصوص

القصة تُروى بجمل معبّرة، لا بسنوات وتواريخ. التاريخ الوحيد الظاهر هو «15 سبتمبر» (تركيب الفرن).
كل لحظة في شريط «الحكاية تكبر» لها سطر حكاية خاص بها (`GROWTH.frames[*].story`).

### الافتتاح (تشويق)

المحل لم يفتتح بعد، لذلك:
- لحظة الوصول (مشهد 8) تحمل «قريبًا · ترقبوا الافتتاح».
- النهاية تعرض شارة «قريبًا» نابضة، و«ترقبوا الافتتاح» يمرّ عليها ضوء، وسطر «الطاولات تنتظر... والنار على وشك أن تشتعل.» (`FINALE.teaser`).
- عند الافتتاح: غيّر `FINALE.teaser` (أو احذفه) و`REVEAL.slate`.

### الروابط

| الزر | الحالة |
| --- | --- |
| اكتشف القائمة | يظهر مع «قريبًا» — ضع الرابط في `LINKS.menu.href` |
| تواصل معنا | يظهر مع «قريبًا» — ضع رقم الهاتف أو رابط واتساب في `LINKS.contact.href` (مثلًا `https://wa.me/970...`) |
| موقعنا | يبحث في خرائط Google عن «بنك فلسطين، شارع حيفا، جنين». بعد إضافة المحل على الخرائط ضع رابط الدبوس الدقيق |
| Instagram | الزر المميّز حاليًا. الرابط مأخوذ من مشروعك السابق — تأكد منه |

أي زر رابطه `#` يظهر تلقائيًا مع كلمة «قريبًا» ولا يفتح شيئًا، وعند وضع الرابط يصبح زرًا عاديًا.

## الصور

### الطريقة الموصى بها (مع تحسين تلقائي)

1. ضع الصورة الأصلية في مجلد [`photo/`](photo/).
2. أضف سطرًا لها في [`scripts/images.config.mjs`](scripts/images.config.mjs):
   ```js
   { in: 'pizza.jpg', out: 'story/pizza' },
   ```
3. شغّل:
   ```sh
   npm run images
   ```
   ينتج `public/images/story/pizza.avif` و`.webp` ونسخة ضبابية صغيرة للخلفيات،
   ويرفع دقة الصور الصغيرة بجودة أفضل من المتصفح.
4. في `story.js` استخدم المسار **بدون امتداد**: `image: { src: '/images/story/pizza' }`

خيارات إضافية في الـconfig:
- `crop: { left, top, width, height }` لقص أجزاء من لقطة شاشة (أسهم Instagram، نقاط، كتابة ستوري).
- `sketch: 'story/اسم'` لإنتاج نسخة "رسم ذهبي" من الصورة (مستخدمة في مشهد المكان).

### الطريقة السريعة

انسخ أي صورة (`.jpg` / `.png` / `.webp`) إلى `public/images/...` واكتب مسارها **مع الامتداد** في `story.js`.

### الصور الناقصة

أي صورة غير موجودة تظهر كإطار واضح مكتوب فيه ماذا نضع ومسار الملف المتوقع.
ضع الملف بهذا الاسم (أو عبر `npm run images`) وسيظهر مباشرة، بدون أي تعديل في الكود.
حاليًا لا توجد صور ناقصة.

### أين تُستخدم صورك الحالية

## نماذج 3D

المطعم والفرن والبيتزا مبنية بالكود (Procedural 3D)، فلا يحتاج الموقع أي ملف نموذج.
الفرن مصمّم على شكل فرنكم النحاسي الحقيقي (قبة نحاسية مطروقة، فتحة سوداء، مدخنة نحاسية)،
وعليه لوحة بشعار 450، وداخله مضاء بالنار نفسها. الواجهة الزجاجية بإطارات سوداء مثل واجهتكم.

### البيتزا الحقيقية داخل الـ3D

في الفرن تتحوّل البيتزا الـ3D إلى **بيتزا 450 الحقيقية** دون أن يختفي أي مكوّن:
- السكربت (`npm run images`) يأخذ صورة البيتزا (`photo/pizza.png`)، يعدّل منظورها إلى منظر علوي دائري،
  ويصنع نسخة "خارجة من الفرن" بدون الريحان والجبنة المبشورة (`pizza-top-clean.webp`)، لأنهما يُضافان بعد الفرن.
- ويحدّد أماكن الجبنة الذائبة في الصورة (`src/data/pizza.cheese.json`)، فتهبط قطع الجبنة الـ3D في تلك الأماكن
  بالضبط، وفي الفرن تذوب وتتمدد وتتحول إلى جبنة الصورة الحقيقية.
- بعد الفرن تُبشر الجبنة فوق مكان كومة الجبنة في الصورة، ويسقط الريحان فوق أماكن الريحان في الصورة،
  ثم تظهر الصورة الكاملة.

كل حركات البيتزا (مسار المغرفة، قطع الجبنة، الريحان، المبشرة) في [`src/three/pizzaPlan.js`](src/three/pizzaPlan.js)،
وأماكن المكونات على الكاونتر في `PIZZA_SET` داخل [`src/three/worldState.js`](src/three/worldState.js).
أسماء المكونات الظاهرة فوقها في `PIZZA.tags` داخل `story.js`.

لاستبدال البيتزا بصورة أخرى: ضع الصورة في `photo/`، وعدّل في `scripts/images.config.mjs` قيم
`topView: { cx, cy, rx, ry }` — مركز وأنصاف أقطار القطع الناقص الذي يحيط بحافة البيتزا في الصورة الأصلية
(بالبكسل) — و`pile` مكان كومة الجبنة المبشورة، ثم `npm run images`. إن تغيّرت أماكن الريحان عدّل
`PHOTO_BASIL` في `src/three/pizzaPlan.js`.

**حماية:** إذا تعذّر تشغيل المؤثرات على جهاز ما تُطفأ وحدها ويستمر الفيلم؛ وإذا تعذّر تشغيل الـ3D كله تظهر
صور حقيقية مكان المشاهد ثلاثية الأبعاد بدل شاشة فارغة.

### فيلم صناعة البيتزا (فيديو AI بدل الـ3D)

فصل «البيتزا» يمكن أن يعرض **فيديو واقعي** لصناعة البيتزا بدل الـ3D، يتحرك إطارًا بإطار مع الـScroll
(للأمام وللخلف). الفيديو مولّد بالذكاء الاصطناعي (Wan 2.2) من صور حقيقية: لقطة الفرن تبدأ من صورة
فرنكم النحاسي، واللقطة الأخيرة تبدأ من صورة بيتزتكم الحقيقية.

**التوليد يتم في السحابة فقط، لا على جهاز الكمبيوتر.** اللقطات وأوصافها في [`film/shots.json`](film/shots.json)،
والصور التي تبدأ منها كل لقطة في `film/keys/`. في جلسة Claude سحابية (claude.ai/code) على هذا المستودع:

```bash
npm install
HF_TOKEN=hf_... npm run film:generate          # يولّد المقاطع الناقصة على كروت Hugging Face
HF_TOKEN=hf_... npm run film:generate -- sauce # يعيد لقطة معيّنة
```

السكربت لا يشغّل أي موديل محليًا: يرفع صورة البداية ويستلم المقطع الجاهز. لا يعمل على Windows
(حتى لا يُشغَّل على جهازك بالخطأ). إذا انتهت حصة الـGPU اليومية يتوقف، وعند تشغيله مرة ثانية يكمل من حيث توقف.
الجلسة السحابية تحتاج: متغير `HF_TOKEN` (من huggingface.co/settings/tokens) ووصولًا للشبكة إلى
`huggingface.co` و`*.hf.space`.

**أو على جهاز Windows فيه كرت NVIDIA (12GB فأكثر)** — فقط عندما يسمح صاحب المشروع بذلك صراحةً:

```bash
npm run film:generate:local                        # يولّد المقاطع الناقصة على كرت الشاشة
npm run film:generate:local -- sauce               # يعيد لقطة معيّنة
npm run film:generate:local -- sauce --seed 4551   # …ببذرة (seed) أخرى
npm run film:generate:local -- --keys              # يكتب صور البداية المجهّزة فقط (للمراجعة)
```

يحتاج ComfyUI (نسخة Windows portable) مع إضافة ComfyUI-GGUF وملفات الموديل المذكورة في `local` داخل
`shots.json` (نفس موديل Wan 2.2 A14B ونفس LoRA والخطوات والمقاس التي تستخدمها Hugging Face). المكان الافتراضي
`C:\ai-cache\ComfyUI_windows_portable` (أو المتغير `COMFYUI_DIR`)، وكل الأوزان خارج المستودع. لكل لقطة:
`crop` (قصّ أقرب مثل عدسة ماكرو) و`focus` (تمويه ناعم للخلفية خارج دائرة)، والوصف `prompt` + `details` +
`style` المشترك. كل محاولة تُحفظ في `film/takes/` (خارج git) مع لوحة من 8 إطارات للمراجعة، وأوقات التوليد في
`film/renders.json`. لحذف كل شيء لاحقًا: احذف المجلد `C:\ai-cache`.

1. المقاطع تُحفظ في مجلد `film/` بأسماء مرتبة، والجزء بعد الرقم هو اسم اللقطة:
   `01-dough` `02-stretch` `03-sauce` `04-cheese` `05-oven` `06-bake` `07-out` `08-finish` (`.mp4`)
2. شغّل:
   ```bash
   npm run film
   ```
   يأخذ الترتيب والقصّ (`trim`) من `shots.json`، ويعطي كل المقاطع نفس تدرّج الألوان (دافئ، وأسود الصفحة
   `#0B0907`)، ويصل كل لقطة بالتالية بذوبان قصير (`dissolve`)، ثم يكتب الفيلم **إطارات WebP** في حجمين:
   `public/video/pizza-film/desktop` (832×624) و`mobile` (576×432)، مع صورة أول إطار، ويكتب
   `src/data/pizza.film.json`. الإطارات تُرسم على `<canvas>`: حزمة «k» (كل ثامن إطار) تُحمَّل أولًا فيصبح الفيلم
   قابلًا للتمرير فورًا، ثم تكتمل الإطارات بينها — الأقرب لموضع القارئ أولًا. (قيس هذا مقابل فيديو MP4:
   الإطارات بقيت على الإطار الصحيح 100% حتى مع معالج أبطأ ×4، والفيديو كان يتأخر أحيانًا.)
3. في `story.js` داخل `PIZZA.film`:
   - `clips`: متى تُعرض كل لقطة داخل الفصل (بالشاشات).
   - `tags`: مكان اسم كل مكوّن على الفيديو (`x`, `y` من 0 إلى 1) ومتى يظهر. أبقِها بين 0.2 و0.8 أفقيًا
     و0.15 و0.85 عموديًا: الشاشة العريضة تقص أعلى الإطار وأسفله، والهاتف يقص جانبيه.
   - `PIZZA.ending`: السطر والأزرار في نهاية الفصل (الرابط الذي ما زال `'#'` لا يظهر، وأول رابط حقيقي هو
     الزر المميّز — عند وضع رابط واتساب في `LINKS.contact` يصبح هو الأول).

لاستبدال لقطة: استبدل ملفها في `film/` بنفس الاسم وأعد `npm run film`.
للعودة إلى نسخة الـ3D: احذف `src/data/pizza.film.json`.

**حماية:** إذا لم يعمل الفيلم على جهاز ما تعود نسخة الـ3D تلقائيًا. أثناء عرض الفيلم يتوقف رسم الـ3D
خلفه لتوفير طاقة الجهاز. الهاتف والاتصال البطيء يحصلان على النسخة الأخف. ومع `prefers-reduced-motion`
تظهر صورة ثابتة لكل خطوة مع أسماء المكوّنات بدل الحركة.

### المظهر السينمائي

[`src/components/RestaurantScene/Effects.jsx`](src/components/RestaurantScene/Effects.jsx):
ظلال تلامس ناعمة (Ambient Occlusion)، توهّج للأضواء والنار (Bloom)، عمق ميدان يركّز على ما تنظر
إليه الكاميرا (Depth of Field)، وTone mapping محايد يحافظ على ألوان الطعام الحقيقية.
الهاتف يتخطى هذه المؤثرات للحفاظ على السرعة.

### استبدال عنصر بنموذج .glb

لاستبدال أي عنصر بنموذج حقيقي (`.glb`):

1. ضع الملف في [`public/models/`](public/models/) — مثلًا `public/models/oven.glb`.
2. في [`src/data/models.js`](src/data/models.js) اكتب:
   ```js
   oven: { url: '/models/oven.glb', scale: 1, position: [0, 0, 0], rotation: [0, 0, 0] },
   ```
3. عدّل `scale` و`position` و`rotation` حتى يجلس مكان القديم.

العناصر القابلة للاستبدال: `oven`, `table`, `chair`, `lamp`, `counter`.
حركات البناء مع الـScroll تبقى تعمل مع النموذج الجديد. إذا فشل تحميل الملف يعود العنصر المبني بالكود تلقائيًا.

نصائح: أبقِ الملف أقل من 2MB، وعدد مضلعات منخفض، ويمكن استخدام ضغط Draco/Meshopt.

---

## الأداء

- **أول تحميل صغير:** ~134KB JS (gzip) + الخطوط. محرك الـ3D مع المؤثرات (~460KB gzip) يُحمَّل في الخلفية
  أثناء مشاهدة الشروق، ويُجهَّز (تجميع الشيدرز ورفع الخامات) قبل الوصول إليه.
- **الـ3D يُرسم فقط عندما يكون على الشاشة** (مشاهد 4–6)، وفي باقي الوقت يتوقف تمامًا.
- **الصور تُحمَّل عند اقتراب مشهدها** فقط، بصيغة AVIF/WebP.
- **الخامات مرسومة بالكود** (الطوب، البلاط، الخشب، الرخام، النحاس، العجين، الصوص) — لا ملفات لتحميلها.
- **الجسيمات على كرت الشاشة** (طحين، بخار، شرر، غبار) — كل نظام draw call واحد.
- **مستويات حسب الجهاز** ([`src/config/quality.js`](src/config/quality.js)): الهاتف يحصل على دقة أقل،
  جسيمات أقل، بلا ظلال حقيقية وبلا blur في النصوص؛ وتنخفض الدقة تلقائيًا إن هبطت سرعة الإطارات.
- الحركات كلها `transform` و`opacity` (GPU)، و`prefers-reduced-motion` يخفف حركات الكاميرا الكبيرة.

تم القياس على نسخة الإنتاج بـScroll حقيقي عبر الفيلم كاملًا: وسيط الإطار 16.7ms (60fps).

### كيف يعمل

```
scroll ─▶ Lenis ─▶ ScrollTrigger (scrub) ─▶ Timeline رئيسي واحد
                                              ├─ مشاهد DOM (صور، نصوص، أقنعة، clip-path)
                                              └─ أرقام worldState ─▶ useFrame ─▶ المشهد الـ3D
```

كل مشهد يسجّل Timeline خاص به بزمن من 0 إلى 1 (`useSceneTimeline`)، والـProvider يمدّه إلى
`duration` المشهد ويضعه في الـTimeline الرئيسي مع تداخل للانتقالات. لإضافة مشهد جديد: أنشئ
مكوّنًا في `Scenes/`، أضفه إلى `SCENES` في `components/Story/Story.jsx`، وأضف سطرًا في `TIMELINE`
داخل `story.js`.
